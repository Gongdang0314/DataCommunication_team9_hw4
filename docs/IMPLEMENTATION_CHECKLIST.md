## 1. 그림과 규칙

- [ ] canvas0/1/2 각각 80행 × 160열, ASCII 32~126, LF, 마지막 LF, 정확히 12,880바이트.
- [ ] 세 장 모두 높이 5줄 이상의 큰 G9와 별도 문구 2개 이상. 문구와 위치는 세 장마다 다름.
- [ ] 점 / (점 + 공백) 비율 4~6%, 공백·점을 제외한 글자 획 384칸 이상.
- [ ] Rule1: 8이웃, 공백 이외는 생명, B3/S23, 탄생 문자 최빈값 및 ASCII 최소 동률 처리.
- [ ] Rule2: 8이웃, @ → + → 공백, 빈칸은 @ 이웃 정확히 2개일 때 탄생.
- [ ] Rule3: 상하좌우 4이웃, RAMP=" .:-=+*#%@", 다음 단계 이웃이 있으면 한 단계 전진.
- [ ] 모든 규칙은 Torus와 이중 버퍼 적용. Worker는 세로를 자체 wrap하지 않고 Halo 이용.
- [ ] Round 1000 직전 canvas1 덧칠 → 공백 아닌 칸 @ 변환. Halo 포함 작업판 전체에 적용.
- [ ] Round 2000 직전 canvas2 덧칠 → 밝기 변환. 원래 y와 team=9 사용. 공백도 변환 대상.
- [ ] 덧칠은 canvas에서 공백과 점을 제외한 글자만 복사.
- [ ] 교수 제공 키트의 작은 규칙·띠·덧칠·변환 정답 통과.
- [ ] G11 샘플은 team=11로 3,000 Round 계산하여 제공된 31개 hash와 일치. 제출 입력은 G9.

## 2. 통신과 동기화

- [ ] 실제 TCP 소켓, 줄 단위 수신 버퍼, sendall 사용. 공백 보존(그림 줄 strip 금지).
- [ ] 원격 Assigner 한 개, 로컬 PC 한 대의 Worker N개 프로세스, Worker 간 연결 없음.
- [ ] IP·port·team·canvas 경로·개발용 N은 인자/설정으로 지정.
- [ ] 기본 N은 매 실행 4~8 무작위. N=1은 기준 실행용이며 로컬 가능.
- [ ] 띠 범위 [80*k//N, 80*(k+1)//N), 접속 순서대로 Worker 번호 배정.
- [ ] N명 HELLO 수신 후 ASSIGN 전달. canvas0 h줄, canvas1/2 각각 h+2줄.
- [ ] Assigner Thread는 Main 1 + Handler N, 접속 단계에서만 생성.
- [ ] 공유 상태는 Mutex 1개로 보호, done_cv와 go_cv 두 Condition을 같은 Mutex에 결합.
- [ ] while 조건 재확인. 전원 RESULT r 도착 전 ROUND r+1 전송 없음.
- [ ] send/recv/파일 저장은 상태 Mutex 밖에서 수행; snapshot 복사 후 저장.
- [ ] ROUND r + Halo 2줄, RESULT r k + 새 첫/끝 줄, 10 Round마다 띠 전체 추가.
- [ ] 모든 RESULT의 r·k 및 그림 줄 길이 검사. 연결 끊김·잘못된 결과는 FAIL 후 종료.
- [ ] RESULT 2999 전원 수신 후 BYE, Handler join, 정상 종료.
